# Gather Feature Context Workflow

This workflow helps gather comprehensive context for a large feature, epic, or initiative by analyzing its details, related tasks, comments, and associated documentation.

## Input

**Required:**
- A clear identifier for the feature or epic (e.g., a title, ID, or link to the main ticket).

## Workflow

### 1. Analyze the Core Feature/Epic

-   **Gather Details:** Collect all available information about the feature, including its summary, description, status, priority, and any labels or components.
-   **Identify Keywords:** Extract key terms and concepts from the feature's description and summary.

### 2. Review Related Tasks and Discussions

-   **List Child Items:** Identify and list all child tasks, stories, or sub-tasks related to the main feature.
-   **Analyze Discussions:** Review all comments and discussions on the main feature and its child items to identify key decisions, stakeholder feedback, and technical considerations.
-   **Expand Keywords:** Add any new keywords or technical terms discovered in the related tasks and discussions to your list.

### 3. Search for Related Documentation

-   **Perform Comprehensive Searches:** Use the keywords you've gathered to search for related documentation in all relevant repositories (e.g., Confluence, Google Drive, project wikis).
-   **Use Creative Search Queries:**
    -   Search for the feature's ID and name directly.
    -   Search for keywords combined with terms like "requirements," "design," "architecture," or "testing."
    -   Filter searches by date to find the most recent documents.
    -   If key stakeholders have been identified, search for documents created or modified by them.
-   **Deduplicate and Organize:** Remove duplicate search results and organize the findings by relevance.

### 4. Synthesize and Present Findings

-   **Create a Summary:** Compile all the gathered information into a concise summary that includes:
    -   An overview of the feature and its goals.
    -   A list of related tasks and their statuses.
    -   A categorized list of relevant documentation.
-   **Request Feedback:** Share the summary with the team and ask for feedback. Confirm which documents are most relevant and should be formally linked or referenced.

### 5. Link and Document

-   **Link Documents:** If your project management tool supports it, link the approved documents directly to the main feature ticket.
-   **Add a Summary Comment:** Post a comment on the main feature ticket that summarizes the findings, lists the linked documents, and provides any key recommendations.

## Best Practices

-   **Be Thorough:** The more thorough you are in gathering context, the better your team's understanding of the feature will be.
-   **Think Broadly:** Don't limit your search to just one or two keywords. Think creatively about related terms and concepts.
-   **Prioritize Relevance:** Organize your findings by relevance to help your team focus on the most important information first.
-   **Get Approval:** Always get confirmation from your team before formally linking documents to a feature.
